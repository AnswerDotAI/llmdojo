Capturing a clean round

Codex stores Responses API items rather than Claude transcript records. Clikernel activity appears as native custom exec calls whose logical operation is tools.mcp__clikernel__execute. A capture isolates one successful active round, removes reasoning and host polling noise, and regenerates stable ids.

Deferred host calls

A slow terminal interaction may be recorded as an initial custom_tool_call_output, followed by a host-level wait function call carrying the real result. collapse_deferred restores the simpler logical call/result pair that belongs in a worked example.

Gating the capture

A template is accepted only when it has one start, one first-try score, paired results, no execution errors, and an output explicitly reporting a clean round.

Capturing from a live session

capture_current remains useful when a clean round has already happened in an interactive Codex thread. It keeps the contiguous native custom-call pairs from the first bootstrap doc(clik, pysk, edsk) call through the first clean score. Host-required skill reads before that call remain live session context rather than becoming stale template content.

The capture is gated before it is converted into the review dialog. A supplied docs list can override the documented-tool metadata; otherwise capture_current derives it from the captured standalone doc(...) cells, so MCP worker identity does not affect the stored template.

Template dialog

A live capture can be curated without replaying the whole thread. pick_turns selects clikernel code exactly, falling back to prefix matching, while pick_calls can select any supported nested tool by name and arguments.

Template store

The store keeps native Responses items plus the clean-round completion id, dojo version, and documented-tool state. It is package data, compiled from the canonical dialog by dojobuild and shipped with the code, so updating llmdojo updates the template with nothing per-user to rebuild.

Launching

Creating a dojo session starts a Codex thread, injects the native template, registers its completion receipt, and seeds the documented-tool state. Appending performs the same injection at the tail of an existing thread after compaction.

Compacting with the DSL

Native Codex compaction is encrypted and needs a model turn; llmsurgery.oai.compact_session instead writes a readable compact-DSL document straight into the rollout, offline. compact_dojo chains the two steps — dsl-compact the thread with earlier rounds stripped out of the document, then append a fresh round — so codexdojo -c resumes a session that is both short and re-demonstrated.

The DSL compact should carry the conversation’s work, not its warm-up: the fresh round appended afterwards supersedes any earlier one. As on the Claude side, a round occupies whole user turns, so strip_dojo chunks the items with the shared _turns and drops the turns that dealt a round; compact_session’s strip hook applies it before anything is compacted. A thread holding nothing but rounds is compacted whole rather than emptied.

Command line

A call_parse CLI mirroring claudedojo’s (the capitalized params declare the short flags: Resume → -r, Compact → -c): every mode prepares a thread and then execs codex resume on it, with standing arguments from launch_config('codex') (the codex_args list in $XDG_CONFIG_HOME/codexdojo/config.toml) and anything the launcher doesn’t recognize forwarded via nested=True. The id comes right after resume, so a stray forwarded token lands in codex’s optional prompt slot rather than stealing the session id; forwarded flag values still need --flag=value form, and the fresh-launch path rejects a stray sess loudly. --sid prints the prepared id and exits. Store builds live in dojobuild.

source

Rebuilding

Run codexdojo --capture to start a clean dojo round in a separate scratch project and write the accepted round to the local template store. The command uses the same packaged capture prompt as Claude, delivered through the scratch project’s AGENTS.md. It also writes template.ipynb beside the store for review. Curate that dialog with reply2dlg and dlg2reply, then rebuild the stores with dojobuild --codex (and --claude). Use --current when the source thread already completed a clean round.
